# fa-flow 文档与开发计划

## 文档放置规则

- `plans/`：功能规划、开发顺序、进度、实施记录和验收步骤。设计决策与约束可保留在对应计划内。
- `adr/`：独立、长期有效的架构决策，记录背景、选择、取舍及替代关系；不维护功能开发进度表。当前原有 6 份文档均以实施计划为主，已迁入 `plans/`；后续有独立决策时再新增 ADR。
- 计划统一命名为 `PLAN-flow-{递增编号}-{内容描述}-{MMDD}.md`。按原始创建日期从早到晚编排 001～007，日期后缀沿用首次日期；同日创建的文档沿用原 ADR 顺序。编号表示创建顺序，不表示开发优先级。

## 进度与验收边界

- 功能编号和历史验收记录保持不变；编号须连同所属 PLAN 使用，避免不同计划中同名编号混淆。
- 迁移只调整文档组织，不重新开发已完成项、不把待验收项自动改为已完成。
- 页面交互由编辑器计划维护，节点字段与运行能力由节点计划维护；共同切片互相引用验收范围，避免重复安排开发。
- 历史方案与现行方案冲突时，遵守对应计划的“计划定位与衔接”和最新明确决策；历史验收不扩大为新方案或全范围验收。
- 需要人工验证的功能保持 `🔍验证中`，提供操作步骤，用户确认后更新为 `✅已完成`；无需人工验证的功能完成必要检查后可标记完成。
- 各功能进度以对应计划清单为准；文档整理已完成不代表全部业务功能开发完成。
