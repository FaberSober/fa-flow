# ADR-001: 加固 fa-flow 动态表单与工作流运行链路

## Status

Accepted（分阶段实施）

## Date

2026-09-14

## Scope

- 后端：`fa-flow/`
- 前端：`frontend/apps/admin/features/fa-flow-pages/`

本文记录动态表单和工作流运行链路的修复基线，不直接修改业务代码。功能状态以“功能清单”为准，完成对应验收后更新进度。

## Context

`fa-flow` 同时承担流程定义、流程实例、任务办理和动态表单能力。运行时会执行动态 DDL/SQL，并需要同时支持 MySQL 和 PostgreSQL 18；流程数据还必须满足租户、主子表、流程状态和前端交互契约。

当前主要风险是：

- 动态表名、字段名、排序和 SQL 片段存在越权及注入边界；
- 租户条件、系统字段和子表归属校验不统一；
- 发布、启动、表单保存、实例绑定和任务办理缺少统一的一致性、幂等和补偿边界；
- 流程模型存在任意反射风险，历史版本和模型结构校验不足；
- 运行时数据库方言、前端表单状态、业务结果和编辑器实例隔离存在可靠性问题。

## Decision

1. 动态表单使用元数据注册表、标识符/操作符白名单和预编译参数；DDL 与数据 CRUD 分离权限并记录审计。
2. 租户、系统字段、主子表归属和流程实例归属由服务端统一校验，主子表写操作在同一事务内完成。
3. 发布、启动和任务办理收敛到命令服务，统一处理状态、权限、幂等、事务及跨资源补偿。
4. 流程模型使用 `handlerCode -> handler` 注册表，禁止根据模型中的任意类名、Bean 名或方法名反射执行。
5. 动态 DDL、字段类型和值转换、元数据查询下沉到 MySQL/PostgreSQL 运行时适配层，历史迁移脚本保持不变。
6. 前端统一表单 mode、只读状态、业务结果处理和配置语义；编辑器状态按组件实例隔离，并补齐 JSON、子表和流程树处理。
7. 每个功能必须配套最小单元/集成测试；涉及租户、动态 SQL、DDL、事务和任务权限的功能必须增加负向测试。

## 功能开发说明

### F-SEC-01 动态 SQL/DDL 收口

- 从元数据注册表生成表名、字段名、排序和筛选条件，禁止用户传入任意 SQL 片段。
- 所有运行时值使用预编译参数；DDL 仅允许受控的表单管理操作，并记录审计信息。
- 已完成基础实现：移除 `${sql}` 通路，动态 CRUD 改为参数化查询，并增加标识符和 DDL 类型校验。
- 验证注入字符、非法标识符/排序字段和越权操作，同时回归正常表单 CRUD。

### F-SEC-02 租户与主子表归属校验

- 租户条件和系统字段由服务端生成或维护，忽略或拒绝客户端伪造值。
- 子表新增、修改、删除同时校验子表 ID、主表 ID、租户 ID 和用户权限。
- 已完成主子表 CRUD、实例绑定和状态关联查询的租户校验，并统一主子表写入事务。
- 增加跨租户、跨主表和伪造系统字段的负向测试。

### F-WF-01 流程发布/启动一致性

- 发布和启动通过统一命令服务校验流程状态、使用范围、表单状态和业务归属。
- 使用有界幂等键；表单保存、引擎启动和实例绑定尽量纳入同一事务，跨资源失败可重试或补偿。
- 当前已具备服务端校验、分布式锁、幂等启动和主子流程事务基础；SYSTEM 表单仍需接入可注册的保存/补偿适配器。
- 验证重复请求、禁用流程、无权限用户、孤儿数据和阶段失败场景。

### F-WF-02 任务办理语义完整

- 通过意见和驳回原因同时传递到引擎及审计记录。
- 按任务状态、办理人/候选人、实例归属和幂等条件校验请求。
- 驳回路径从流程配置读取，不使用固定终止行为。

### F-WF-03 处理器注册表替代任意反射

- 使用服务端维护的 `handlerCode` 注册表，并声明输入类型、场景和权限。
- 审计历史模型中的类路径；无法映射的模型进入人工修复或只读状态。
- 验证非法处理器配置不能执行，已登记处理器仍能正常获取候选人。

### F-WF-04 流程定义版本和模型校验

- 历史实例按绑定的部署 ID、版本或快照解析，不按流程 key 直接取最新定义。
- 发布前校验节点、分支、路由、处理人配置和必要版本字段。
- 验证新旧版本并存时的详情、待办和办理结果，以及非法模型拒绝发布。

### F-DB-01 运行时 MySQL/PostgreSQL 方言适配

- 根据数据库类型分别实现动态 DDL、元数据查询、布尔/JSON/自增字段和值转换。
- 运行时 SQL 不混用方言；已发布迁移脚本不回改，新增升级脚本保持可重入。
- 分别验证 MySQL 5.7 和 PostgreSQL 18 的建表、字段变更、CRUD、元数据读取和类型回显。

### F-FE-01 表单编辑/查看和提交结果契约

- `FaFlowForm`、`FlowFormView`、`FormEdit` 等组件显式传递 mode、数据、提交回调和只读状态。
- 编辑态调用真实更新 API；查看态移除新增、编辑、删除等修改入口。
- 只有 HTTP 和业务状态均成功时才关闭页面或刷新数据，失败时保留输入并展示错误。

### F-FE-02 表单配置语义和子表稳定性

- 使用配置中的完整 `rules`；修正 Checkbox/Switch/Select 的值绑定。
- 为子表生成稳定行键，正确处理空值清空，并将 disabled 状态传递到所有操作。
- 验证规则回显、布尔值、Select、子表增删和空数据场景。

### F-FE-03 编辑器实例隔离和树遍历

- 使用实例级 store/context，避免同页多个流程编辑器互相覆盖。
- 缩略图只渲染静态投影；树遍历覆盖条件、并行、包容、路由及其分支。
- 保持 Hook 调用顺序稳定，并验证多实例、节点删除和组件切换场景。

### F-ROBUST-01 解析、Mapper 和 API 契约修复

- 集中处理 JSON 解析失败，页面显示可恢复错误状态。
- 修正 Mapper 参数名、`@Param` 包引用和前后端删除接口路径。
- 增加模型/表单 JSON、任务查询和删除接口的契约测试。

### F-OPS-01 生产日志和提醒治理

- 移除测试提醒及 `System.out/err`，统一使用项目日志组件。
- 为提醒增加环境/租户开关和幂等控制，日志保留可检索上下文且不记录敏感表单值。
- 验证生产环境加载组件时不会自动发送测试提醒。

## Acceptance Gates

当前版本合并前至少满足：

1. 动态 SQL 无任意片段执行，跨租户、跨主表、伪造系统字段和越权任务的负向测试通过。
2. 发布、启动、表单保存、实例绑定和任务办理的失败/重试行为可测试、可观测、可补偿。
3. MySQL 5.7 和 PostgreSQL 18 均通过动态表、字段变更、CRUD、元数据和类型回显验证。
4. 前端编辑、查看、审批和业务失败场景不会误关闭、误刷新或伪造成功。
5. 受影响的后端编译、前端 TypeScript 检查和新增测试通过，且不依赖生产数据。

后续版本功能沿用对应功能说明中的验收条件，完成后再更新功能清单状态。

## Consequences

### Positive

- 动态表单从任意字符串执行收敛为受控元数据和参数化操作。
- 租户、主子表、流程状态和前端编辑/查看契约边界更清晰。
- 工作流和表单数据具备可重试、可补偿的实施路径，双数据库行为更可预测。

### Negative

- 需要增加元数据注册、权限审计、幂等/补偿、迁移和测试成本。
- 历史动态表、流程模型和前端数据可能需要人工迁移或兼容处理。

### Neutral

- 不要求替换 FlowLong，也不要求一次性重写页面；可保留 API 外形并逐步接入内部命令服务。
- 已发布 SQL 不回改，兼容修复通过新脚本、升级执行器或运行时适配完成。

## Alternatives Considered

- **黑名单和字符串过滤**：拒绝，无法可靠覆盖 SQL 语法和数据归属问题；采用注册表、白名单和参数化。
- **只修前端**：拒绝，前端禁用不能替代服务端租户、权限和动态 SQL 校验。
- **继续任意反射**：拒绝，改用受控处理器注册表并对历史模型做迁移审计。
- **复制一套 PostgreSQL 字符串**：拒绝，改用按数据库类型隔离的运行时适配层。

## Risks and Rollback

- 历史元数据或模型不合规时，先扫描并进入迁移/只读清单，不通过放宽校验兜底。
- 跨资源事务失败时，保留幂等键和关联状态，使用可观测、可暂停的重试/补偿任务。
- 方言或前端契约回归时，优先回退适配层/兼容层，并保留双数据库和接口契约测试。
