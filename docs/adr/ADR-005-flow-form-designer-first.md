## 开发说明

### F-FM-01 页面框架与直接入口

- 新建表单直接打开全屏设计器，包含左侧控件、中间画布和右侧属性区。
- 第一阶段可用空白状态和少量演示字段检查布局，不等待后端接口。

### F-FM-02 画布交互与属性面板

- 支持拖入、选中、排序和删除控件；右侧编辑名称、必填、默认值和选项等常用属性。
- 先用页面状态保存交互结果，同时定义最小可序列化字段模型：稳定字段标识、平台无关业务类型、数据/布局区分。
- 分组、说明和分隔线等布局控件不代表数据库列；明细表保留为高级控件。

### F-FM-03 表单与列表预览

- 根据页面中的字段模型生成填报预览和列表默认列、搜索条件。
- 用户可以直接在页面内切换预览并检查结果；不要求列表配置完成后才可继续。

### F-FM-04 配置读取与保存

- 交互模型稳定后，接入真实草稿创建、读取和保存接口，替换临时页面状态/演示数据。
- 保存草稿只持久化表单元数据，不隐式发布数据库结构。

### F-FM-05 发布校验及双库表结构

- 发布时校验字段配置、展示易懂的结构变更摘要，再调用受控的动态 DDL。
- 动态 DDL、字段元数据读取、值转换和 CRUD 沿用 ADR-001 F-DB-01 适配；前端不暴露数据库方言或 SQL 类型。
- 对可能影响已有数据的字段变更给出影响和处理选择，不静默丢弃数据。

### F-FM-06 已有表绑定策略（待确认）

- 确认新建表单是否支持绑定任意已有表；如支持，放在高级入口并校验字段映射和兼容性。
- 在策略确认前，默认新建路径由系统管理表结构；已有表单需继续可查看和运行。

## Context

当前表单配置依次暴露数据库表结构、拖拽表单和列表查询配置，要求用户理解表、字段及关联关系。相关入口和组件包括 `FlowFormConfigDrawer`、`FormTableEdit`、`FaFormEditor` 和 `TableShowDesign`。该流程把实现细节放进了普通用户的必经路径。开发顺序采用页面优先，让布局和交互尽早可在浏览器中验证，再逐步接入保存和数据库发布能力。

## Decision

1. 先交付可直接打开和操作的设计器页面，再逐步补齐预览、接口持久化和数据库发布闭环。
2. 页面阶段使用临时页面状态/演示数据；它只服务交互开发，不作为长期模拟接口。
3. 在画布交互阶段定义最小可序列化字段模型，以平台无关业务类型驱动表单、存储和列表默认配置。
4. 新建表单默认进入全屏三栏设计器；模板和高级设置为可选能力。
5. 列表查询配置自动提供可用默认值，允许预览和调整，但不作为发布前置条件。
6. 草稿编辑与发布分开；MySQL/PostgreSQL 运行时适配沿用 ADR-001 F-DB-01。已有任意表绑定能力暂不定为新建主流程。

## Consequences

### Positive

- 用户可以从熟悉的拖拽设计开始，不必先理解数据库表和查询参数。
- 字段配置集中后，表单和列表可共享定义，降低重复配置及上下层不一致。
- 数据库方言留在后端适配层，前端不因 MySQL/PostgreSQL 分叉。
- 页面交互可先于后端完成，便于通过浏览器尽早收集布局和使用反馈。

### Negative

- 需要梳理现有配置格式，并保证已保存表单继续查看、运行和编辑。
- 发布需要识别字段结构变化；字段删除或类型调整需定义数据保护策略。
- 页面阶段使用临时状态，尚不代表数据已持久化或表结构已发布，需在界面和进度记录中区分。

## Alternatives Considered

- **数据库向导作为主流程：** 不采用。表、字段和关联键对普通用户过于技术化。
- **表单、列表和存储继续分别配置：** 不采用。会延续重复操作和配置不一致风险。
- **自由画布作为唯一入口：** 不采用。保留模板及属性面板，降低空白起步和高级配置门槛。

## 验收标准

- 新建表单默认打开设计器；拖入数据字段后可设置属性并保存、重开。
- 后端接口接入前，可在页面内完成添加、排序、编辑、删除和预览交互。
- 纯布局控件不产生存储字段；列表预览可由字段配置生成默认列和查询项。
- 普通创建路径不要求单独建表或配置列表查询。
- 草稿接口接入后，配置可保存并重新读取；未发布草稿不修改物理表结构。
- MySQL 与 PostgreSQL 上表单创建、字段变更、数据写入和读取行为符合相同业务语义。
- 发布前可查看结构变更摘要；影响已有数据的变更不会被静默执行。

## 待确认事项

- 新建表单是否允许绑定任意已有数据库表；若支持，限定为高级配置并明确兼容规则。
- 支持的 MySQL/PostgreSQL 版本及字段类型交集按 ADR-001 F-DB-01 确定。
