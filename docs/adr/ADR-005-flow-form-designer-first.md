## Status

Accepted（表单优先，分阶段实施；已有设计器功能保留验收记录，新增闭环功能待开发）

## 开发说明

### F-FM-01 页面框架与直接入口

- 新建表单直接打开全屏设计器，包含左侧控件、中间画布和右侧属性区。
- 第一阶段可用空白状态和少量演示字段检查布局，不等待后端接口。

### F-FM-02 画布交互与属性面板

- 支持拖入、选中、排序和删除控件；右侧编辑名称、必填、默认值和选项等常用属性。
- 先用页面状态保存交互结果，同时定义最小可序列化字段模型：稳定字段标识、平台无关业务类型、数据/布局区分。
- 分组、说明和分隔线等布局控件不代表数据库列；明细表保留为高级控件。

### F-FM-03 表单与列表预览

- 根据页面中的字段模型生成填报预览和列表默认列、搜索条件。
- 用户可以直接在页面内切换预览并检查结果；不要求列表配置完成后才可继续。

### F-FM-04 配置读取与保存

- 交互模型稳定后，接入真实草稿创建、读取和保存接口，替换临时页面状态/演示数据。
- 保存草稿只持久化表单元数据，不隐式发布数据库结构。

### F-FM-05a 发布前配置检查与字段摘要

- 发布前检查数据字段名称、选择项配置，并展示字段名称、控件类型、必填状态和选项数量。
- 此检查只验证草稿配置，不创建或修改数据库表；实际发布流程按 F-FM-05b 的最小闭环逐步接入。

### F-FM-07a/F-FM-07b 简化设计与管理路径

- F-FM-07a：将名称和分类直接放在设计页面，与字段配置一起创建/更新草稿；显示未保存/已保存状态，页面返回时提示未保存修改，保存失败保留输入，保存期间避免重复请求与字段修改。
- F-FM-07b：继续简化管理列表、控件和属性操作，统一预览及发布入口；不以 F-FM-07a 完成代表整体体验重构已经完成。
- 以普通用户的“新建 → 添加字段 → 预览 → 保存/发布”为主路径，先梳理现有页面，不重做无关组件。
- 控件和属性优先覆盖常用输入，统一操作文案与状态提示；表名、SQL 类型、存储映射由系统处理。
- 复用现有设计器和填报组件，避免为了未来扩展先建设通用框架。

### F-FM-05b 最小可用发布闭环

- 将 `config.designer.items` 转为现有填报组件可消费的配置，并生成 `dataConfig` 和默认 `tableConfig`；字段标识保持稳定，布局控件不生成数据库列。
- 接通真实后端发布接口：读取草稿、转换配置、创建表/必要字段、保存生效配置；发布成功后可以进入真实填报和数据列表。
- 第一切片以新表单和基础字段为范围，明确支持的控件和类型；按此范围实现 ADR-001 F-DB-01b/c，不等待全部字段变更和高级类型适配完成。
- 在当前开发使用的数据库上先跑通整体链路，再验证另一数据库的同范围行为；双库完整矩阵不作为每个前期切片的前置条件，也不提前宣称双库完成。
- 发布前展示业务字段摘要，失败时保留草稿并提示失败阶段；先保证正常发布和基本重试不重复建表，不先建设通用补偿系统。
- 前期不开放已有数据的删列、类型收窄等破坏性修改；完整结构差异和迁移选择在 F-FM-09 完善。

### F-FM-08 独立填报与数据管理

- 表单无需绑定流程即可填写、提交、保存、重开、编辑和查看数据。
- 列表自动生成常用列与基础查询项，用户不必先配置列表才能使用表单。
- 接通真实新增、更新、详情和列表接口；业务失败时保留输入，不触发成功回调。
- 与 ADR-001 F-FE-01 协同统一提交和只读语义，避免另建一套运行表单。

### F-FM-09 草稿、发布配置与修改策略

- F-FM-05b 首次发布先保留最小的草稿/生效配置边界，保存草稿不改变正在使用的表单；启用/禁用不等同于发布状态。
- 独立闭环跑通后，再完善版本记录、结构差异和重复发布行为；不要求前期交付完整历史版本管理。
- 优先支持新增字段等兼容修改；删除字段和改变类型需明确已有数据处理，不能静默丢弃数据。
- 保持已保存的旧表单可查看和运行，按需增加配置转换兼容层。

### F-FM-10 表单接入流程引擎

- 表单独立闭环基本完善后，再按 ADR-004 推进表单选择、流程发起、节点字段权限和审批展示。
- 首先用一个简单审批流程跑通真实联动，再扩展分支、辅助节点和复杂办理规则。
- 基于已经稳定的字段定义与运行配置联动，不让流程节点扩展成为表单重构的前置条件。

### F-FM-06 已有表绑定策略（待确认）

- 确认新建表单是否支持绑定任意已有表；如支持，放在高级入口并校验字段映射和兼容性。
- 在策略确认前，默认新建路径由系统管理表结构；已有表单需继续可查看和运行。

## Context

当前表单配置依次暴露数据库表结构、拖拽表单和列表查询配置，要求用户理解表、字段及关联关系。相关入口和组件包括 `FlowFormConfigDrawer`、`FormTableEdit`、`FaFormEditor` 和 `TableShowDesign`。该流程把实现细节放进了普通用户的必经路径。已有页面、预览和草稿保存已通过阶段验收，但设计器配置与运行填报、存储映射仍需接通。当前优先重构表单管理的使用路径，尽早跑通网页到后台的真实闭环，待表单基本完善后再推进流程联动。

## Decision

1. 表单是独立基础能力，先完成“新建 → 设计 → 预览 → 发布 → 填报 → 数据管理”，再与流程引擎结合。
2. 前期优先正常使用路径和真实前后端接口，不以全面安全加固、完整测试矩阵或高级功能作为开发前置条件。
3. 以最小可序列化字段定义驱动设计、运行表单、存储和默认列表；先复用现有配置与组件，再按实际需要调整模型。
4. 新建表单默认进入设计器，自动处理数据库配置和列表默认值；模板和高级设置可后续完善。
5. 草稿与生效配置分开，采用足以支撑当前链路的最小实现；复杂版本管理、迁移和补偿后置。
6. MySQL/PostgreSQL 沿用现有适配方向，按当前开发环境和受支持字段分切片接通；任意已有表绑定继续待确认。
7. 保留已有参数化 SQL、租户隔离、系统字段保护和权限控制；新增校验只覆盖当前功能必要条件，不为未开放能力增加限制。
8. 验证以一个真实表单的端到端人工冒烟为主，辅以受影响范围的编译/静态检查；自动测试按缺陷和关键风险补充，不要求每个功能新增测试或每次全量构建。

## Consequences

### Positive

- 用户可以从熟悉的拖拽设计开始，不必先理解数据库表和查询参数。
- 字段配置集中后，表单和列表可共享定义，降低重复配置及上下层不一致。
- 数据库方言留在后端适配层，前端不因 MySQL/PostgreSQL 分叉。
- 页面交互可先于后端完成，便于通过浏览器尽早收集布局和使用反馈。

### Negative

- 需要梳理现有配置格式，并保证已保存表单继续查看、运行和编辑。
- 发布需要识别字段结构变化；字段删除或类型调整需定义数据保护策略。
- 页面阶段使用临时状态，尚不代表数据已持久化或表结构已发布，需在界面和进度记录中区分。

## Alternatives Considered

- **数据库向导作为主流程：** 不采用。表、字段和关联键对普通用户过于技术化。
- **表单、列表和存储继续分别配置：** 不采用。会延续重复操作和配置不一致风险。
- **自由画布作为唯一入口：** 不采用。保留模板及属性面板，降低空白起步和高级配置门槛。

## 分阶段验收标准

### 前期：网页到后台的独立闭环

- 使用一个包含文本、数字、日期、选择等已支持字段的测试表单，完成新建、设计、预览、草稿保存和重开。
- 发布调用真实后端并生成运行配置及存储映射；无需手工建表或配置列表。
- 不绑定流程即可新增数据，列表可见，详情重开值正确，编辑后可再次读取；查看态不能修改。
- 草稿保存不修改已生效配置；发布或提交失败保留内容并提示，不伪造成功。
- 纯布局控件不产生存储字段，前期不开放有损字段修改。
- 对受影响代码执行最小充分检查，并记录实际验证的数据库、字段范围和未支持能力；无需全量构建、全量测试或完整双库矩阵。

### 独立闭环后：维护能力与流程联动

- 验证另一数据库的同范围发布和 CRUD，再逐步补齐双库字段变更与类型语义。
- 验证草稿/发布配置隔离、兼容字段修改以及已有数据保护。
- 使用一个简单审批流程完成表单选择、发起、审批展示与节点字段权限联动，再扩大节点和办理场景。
- 全面安全负向测试、复杂并发/补偿和运行治理按 ADR-001 后续阶段实施。

功能实现后需要人工验证的标记为 `🔍验证中`；用户确认验证成功后再标记为 `✅已完成`。

## 待确认事项

- 新建表单是否允许绑定任意已有数据库表；若支持，限定为高级配置并明确兼容规则。
- 支持的 MySQL/PostgreSQL 版本及字段类型交集按 ADR-001 F-DB-01 确定。

## F-FM-07a 人工验证步骤

1. 从 `/admin/flow/manage/form` 点击“新建表单”：页面直接显示名称和分类输入，不再弹出首次保存信息框。填写名称/分类，添加文本和选择字段，修改名称、必填和选项后预览，确认基本交互正常。
2. 点击“保存草稿”：应提示成功，地址带草稿 ID，名称、分类和字段保留，标记为“草稿已保存”。返回列表重新打开“设计”，确认这些信息从后台正确回显。
3. 在同一草稿中修改表单名称、分类以及字段属性，确认出现“有未保存的修改”；保存、返回列表并重开，确认更新已持久化，列表中的名称和分类同步更新，未新增重复记录。
4. 修改一个字段后点击页面左上角返回：选择“继续编辑”保留内容，选择“放弃修改并返回”后重开应恢复上次保存值。另做一次修改后刷新页面，确认浏览器显示离开提醒；取消刷新后继续编辑（浏览器可能使用自己的提示文案）。
5. 临时断开网络后修改并保存：应提示失败，输入和未保存状态保留，恢复网络后可再次保存成功。清空名称或分类再保存，应在对应位置提示必填，不发送无效保存请求。
