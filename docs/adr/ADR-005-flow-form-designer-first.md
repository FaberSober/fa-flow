# ADR-005: 在现有数据库表、表单和列表配置上完善独立使用闭环

## Status

Accepted（2026-10-02 调整：移除新设计器方案，复用已有三步配置；表单优先、流程后续接入）

## Date

2026-09-26；方向调整：2026-10-02

## Scope

- 后端：`fa-flow/`；前端：`frontend/apps/admin/features/fa-flow-pages/`。
- 当前主入口：`/admin/flow/manage/form` → 配置 → 数据库表 / 表单设计 / 列表设计。
- 管理员具备基础数据库知识，负责表结构和配置维护；普通用户使用配置好的表单和数据列表。
- 先跑通网页到后台的独立填报闭环，再推进流程发起、字段权限和审批展示。保留现有安全边界，以最小充分验证支持方向调整。

## Context 与 Decision

现有系统已提供数据表创建/选择、字段维护、表单控件及数据库字段映射、列表和查询配置。新建另一套以随机字段标识生成数据表的设计器，增加维护入口，并使后续业务代码、SQL 和数据理解困难。

本次决定移除新设计器及其自动建表发布方式，在原有功能上优化。管理员先创建或选择业务数据表，明确有业务含义的表名和字段名，再配置表单和列表。控件自身的内部 ID 可以保持独立，但数据库字段名和业务映射必须来自管理员维护的表结构。

- 恢复原有新增信息弹框和统一“配置”入口，管理列表保持完整功能，不增加简单/高级切换。
- 移除新设计器组件、随机表字段生成器及 `publishDesigner` API；旧设计器地址仅重定向至表单管理。
- 不删除已有表单记录、物理数据表或数据，不自动重命名已有随机表/字段。旧草稿可从原配置入口选择数据表、重新配置；已生成的表可通过原配置入口继续维护。
- 保留能复用于原链路的真实新增/编辑提交、只读展示、日期/多选/空值回显、原始数据库字段排序及数据库方言修复。
- 命名规范在已有数据表设计界面实施，提供业务表名、字段名、注释的提示和必要校验，不另建一套数据表设计器。

## 开发顺序与验收边界

1. F-FM-11：恢复唯一维护入口，确认已有配置及数据仍可使用。
2. F-FM-12：在原数据库表界面完善有业务含义的命名和基础字段维护，再进入表单及列表设计。
3. F-FM-13 / F-FM-14 / F-FM-08：按一个实际业务表逐步跑通配置保存、重开、填报、查看、编辑及查询，不要求一次实现全部高级控件。
4. F-FM-09：围绕实际结构修改需求处理兼容和已有数据保护。
5. F-FM-10：表单模块基本完善后推进整个流程模块。

表名建议使用业务模块前缀和小写下划线，如 `ff_crm_customer_feedback`；业务字段如 `customer_name`、`feedback_content`。提供中文表/字段注释，系统字段由系统补齐。规范调整不强制重命名旧表和旧字段。该规范的 UI 提示与校验由 F-FM-12 在原页面实施，旧表和旧字段无需自动重命名。

数据库字段修改沿用已有接口，并按受影响操作逐步适配 MySQL/PostgreSQL，与 ADR-001 F-DB-01b/c 协同；不能将基础建表/结构读取完成视为全部字段增删改已经完成。

需要人工验证的功能标记 `🔍验证中`，用户确认后标记 `✅已完成` 并提交相关代码。历史新设计器的验收结果不作为原配置链路的验收结果。

## F-FM-12 数据库表设计优化切片

- 范围：原数据库表配置页面，覆盖新建/选择业务表、基础字段新增/更新/删除、结构读取、配置同步和重开。数据库类型由服务端当前连接确定，页面展示 MySQL/PostgreSQL 标记，按类型显示字段参数。
- 系统字段 `id`、`flow_instance_id`、`tenant_id`、`crt_time`、`crt_user`、`upd_time`、`upd_user`、`deleted` 默认隐藏，按钮可切换显示；展开为系统维护的只读区域。隐藏只影响展示，排序和同步始终保留完整字段集合，不删除物理字段或配置映射。
- 双库字段 DDL 分方言处理，补齐类型、默认值、注释、主键和自增等回显；长度仅用于字符类型，定点小数使用总精度和小数位，整数不使用显示宽度。保留现有受管理表及系统字段边界，暂不支持字段重命名和自动强制转换已有数据。
- 默认值区分无默认与固定值，日期时间支持受控的当前时间表达式。已有不支持的默认表达式保留并提示，避免按字符串覆盖。不新增任意 SQL 输入功能。
- 刷新结构只重新读取数据库；同步到配置将完整结构保存到表单/子表映射。基础操作成功后才刷新、清空或关闭，失败保留输入。原表单设计和列表设计仍按已有路径使用同步后的映射。
- 已有 unsigned、主键/自增、生成列、ON UPDATE、带时间或浮点精度以及复杂默认表达式等字段暂不支持属性更新，保留原定义并提示原因，避免整列修改时丢失旧属性。新建采用常用基础类型；其他旧类型可读取，暂不承诺编辑。
- 该切片不包含任意旧表迁移、完整索引/外键管理、主键修改、复杂结构变更和所有数据库类型矩阵。ADR-001 F-DB-01b 的整体范围仍待后续验收，不能用本切片替代全部加固。
