## Context

当前流程设计页已经具备画布、节点选择和右侧配置面板，但节点属性仍是分散的部分实现：审批人、表单权限、条件、路由、定时器和触发器各自已有雏形，尚未形成完整的 FlowLong JSON 编辑闭环。

项目实际依赖 FlowLong `1.2.7`，前端类型不能直接照搬官网最新模型。节点配置必须以本地引擎模型、后端人员解析逻辑和办理端实际消费字段为准。

## Decision

1. 采用“公共模型契约与校验优先，再按能力分组纵向开发”的顺序，不按所有节点一次性铺开，也不机械地逐个节点开发。
2. 先修复节点查找、分支上下文、表单状态、字段路径和时间格式等公共问题，再开发发起/审批主链。
3. 复用现有 Store、类型、人员选择器、表单字段收集逻辑和 `FlowProcessSelect`，不新增依赖或通用配置框架。
4. 条件、并行、包容和路由分支按 FlowLong 各自的运行语义实现；并行分支不增加条件编辑器。
5. 只有被本系统办理端和后端实际消费的字段才作为已生效配置开放。仅能写入 JSON 但没有运行时行为的字段不得伪装成完成状态。
6. 未实现的事件、通知和超时 Tab 暂时隐藏或标记为未支持，避免保留空配置面板。
7. 前端校验用于提前提示，后端和 FlowLong 部署校验仍是最终边界。

## 开发说明

### F-NC-01 流程模型契约与校验

- 以本地 FlowLong `1.2.7` 的 `NodeModel`、`ConditionNode` 和 `ProcessModel` 对齐前端类型。
- 校验 `nodeKey` 唯一、人员配置、条件配置、路由目标、定时器、触发器和子流程 Key。
- 不使用本地引擎不存在的字段；例如 `conditionMode` 需先确认引擎支持后再开放。

### F-NC-02 节点选择与配置分派

- 让节点查找结果携带父分支和分支类型信息。
- 正确分派 `conditionNode`，避免选中条件分支后显示空面板。
- 保持只读模式可查看节点，但不能修改节点配置和流程结构。

### F-NC-03 表单状态与字段映射

- 节点切换或流程重载后，表单值必须跟随当前节点刷新。
- `nodeAssigneeCodePath` 等扩展字段统一保存到 `extendConfig`。
- 定时器和触发器统一处理模型字符串与界面时间对象的转换。

### F-NC-04 发起人和发起节点配置

- 复用现有角色、用户和表单选择组件，完善发起人类型回显和保存。
- 保留并完善提交、暂存、撤回、催办、打印、标题和错误规则等已存在扩展配置。
- 没有后端契约的流程事件、通知和独立超时功能暂不开放。

### F-NC-05 审批人配置

- 支持指定成员、直属主管、角色、部门、发起人、发起人本人、多级主管和指定候选人。
- 代码路径保存到 `extendConfig`，候选人配置按 FlowLong 1.2.7 的模型字段保存。
- 复用现有用户、角色、部门选择器，不新增人员选择体系。

### F-NC-06 审批规则配置

- 根据本地引擎枚举实现审批方式、会签/或签/票决和通过比例配置。
- 完善超时自动审批、提醒、自审、驳回策略和驳回目标。
- 每个界面选项都必须对应本地引擎或后端已有字段，不能只做视觉配置。

### F-NC-07 表单权限配置

- 复用现有表单字段收集逻辑，支持普通字段、容器字段和子表字段。
- 修复表单重新打开、节点切换、字段删除后的权限回显和清理。
- 验证 `formAuth` 在办理端确实影响字段的只读、编辑和隐藏状态。

### F-NC-08 操作权限配置

- 追踪转办、回退、加签、减签、追加节点和抄送字段的后端及办理端消费路径。
- 已有运行时支持的字段纳入配置面板；未支持的字段保持待确认或拆为后续任务。
- 不以“JSON 保存成功”作为操作权限功能完成标准。

### F-NC-09 条件与包容分支

- 优先从流程表单元数据中选择条件字段，减少自由文本字段名错误。
- 支持操作符、值、条件组以及 AND/OR 组合，并校验条件完整性。
- 按 FlowLong 运行语义处理条件顺序、默认分支和多个满足条件的包容分支。

### F-NC-10 并行分支

- 支持分支名称、顺序和子节点结构检查。
- 不复用条件分支编辑器；并行分支不配置条件表达式。

### F-NC-11 路由分支

- 复用现有节点树选择目标节点。
- 校验目标节点存在、不能自循环，并确认保存值符合 FlowLong `1.2.7` 的路由格式。
- 路由条件与目标节点删除后的失效状态需要明确提示。

### F-NC-12 抄送、定时器、触发器和子流程

- 抄送节点按本系统实际支持范围完善用户、角色、部门或代码路径选择。
- 定时器统一固定时长、日历时间和模型格式校验。
- 触发器支持立即/延迟触发，并校验 `extendConfig.time`、`args` 和 `trigger`。
- 子流程复用 `FlowProcessSelect`，确认保存流程 Key，并支持同步/异步配置。

### F-NC-13 配置保存与流程运行验收

- 验证编辑、保存、重新打开、只读查看和节点切换不串值。
- 使用真实后端完成部署、启动、审批人解析、分支、驳回、定时器、触发器和子流程冒烟测试。
- 受影响前端执行局部 lint/typecheck 和定向测试，不要求无关模块全量构建。

### F-FUTURE-01 流程事件、通知和独立超时策略

- 先确认后端接口、任务办理端和消息中心的字段消费方式。
- 形成独立的模型与运行时契约后，再决定是否加入当前节点配置面板。

## Non-Goals

- 不替换 `FaWorkFlow`、`ZoomPanEditor` 或现有 DOM 流程节点渲染方案。
- 不升级 FlowLong 版本。
- 不引入新的通用表单设计器或流程配置 DSL。
- 不在本期实现流程历史版本、多人协同编辑和大规模流程图渲染迁移。

## Acceptance Gates

1. 所有已规划执行的功能均能保存、重新打开并正确回显对应节点 JSON。
2. 条件、并行、包容和路由分支分别符合 FlowLong `1.2.7` 的运行语义。
3. 审批人配置能被后端正确解析，表单权限能在办理端真实生效。
4. 操作权限只有在办理端和后端链路验证通过后才标记为完成。
5. 发布、启动、只读查看、节点切换、主题和现有画布交互无回归。
6. 受影响模块的局部检查和定向测试通过。
