# ADR-002: 流程设计全屏编辑器与缩放面板底座优化

## Status

Accepted（本期开发已完成，🔍验证中；人工验收通过后更新为 ✅已完成）

## Date

2026-09-20

## Scope

- 前端：`frontend/apps/admin/features/fa-flow-pages/`
- UI 基础组件：`frontend/fa-ui/packages/ui/src/components/base-modal/FaFullContentModal.tsx`
- 页面：`/admin/flow/manage/deploy`

本文只调整流程编辑页面的容器、标题栏和画布交互底座，不改变流程模型、节点业务规则和后端接口。

## Context

流程编辑页需要承载基础信息、流程设计和扩展配置三个步骤。当前页面已经引入全内容弹框的方向，但标题栏插槽、步骤切换、发布/取消操作和画布缩放逻辑需要形成统一约定。

流程设计画布的主要问题是：

- `ZoomPanEditor` 同时处理缩放、平移、初始适配、小地图和全局键盘监听，职责集中且存在重复实现；
- 主画布和小地图直接渲染同一组业务节点，可能重复创建抽屉、弹出层和状态订阅；
- 变换后的 DOM 尺寸被用于画布适配和小地图计算，容易造成缩放后测量不稳定；
- 窗口尺寸、节点结构变化、只读态和主题样式缺少统一的交互边界。

## Decision

1. 使用 `FaFullContentModal` 作为流程编辑页唯一的全内容容器。标题和返回操作保留在左侧，步骤放在标题栏中间，发布和取消放在右侧；使用自定义标题栏操作时关闭默认底部确认/取消按钮，避免重复操作。
2. 保留当前 DOM 工作流节点实现，优先加固 `ZoomPanEditor`，不在本次引入 Canvas、React Flow 或新的流程渲染框架。
3. 缩放和平移只保留一套状态控制实现；将画布内在尺寸、变换层和可视区域分层，所有适配和小地图计算基于未变换的流程图尺寸。
4. 小地图使用静态投影或独立渲染内容，不复用带抽屉、弹出层和编辑按钮的业务节点；小地图只负责导航视口。
5. 不改变发布、取消、节点编辑和流程模型数据契约；缩放底座完成后再按验收标准更新功能进度。

## 开发说明

### F-EDIT-01 全内容弹框迁移

- `FlowProcessEdit` 使用 `FaFullContentModal`，复用组件已有的 Tab 面板挂载和全内容布局能力。
- 保持编辑器内容区域可伸缩，页面主体不再额外实现一套全屏弹框。
- 保留编辑态、只读态、打开重置步骤和关闭回调的现有语义。

### F-EDIT-02 步骤与操作布局

- 通过 `headerCenter` 放置三步 `Steps`，通过 `headerExtra` 放置“发布”和“取消”。
- 使用自定义操作时关闭 `showOk`、`showCancel`，避免标题栏和底部出现重复按钮。
- 发布前继续校验基础信息；取消只关闭编辑器，不改变当前流程数据。

### F-ZOOM-01 统一缩放控制器

- 以一个 Hook/控制器维护 `zoom`、`offset`、拖拽状态、适配和重置方法。
- 删除未使用的重复状态、初始值和全局逻辑，所有事件监听都在编辑器卸载时清理。
- 为最小/最大缩放比例、缩放步长和适配行为提供稳定的内部配置。

### F-ZOOM-02 分层与尺寸测量

- 将视口、流程图内容和变换层拆开：视口负责裁剪，内容层提供未变换尺寸，变换层负责 `translate + scale`。
- `ResizeObserver` 观察视口和流程图内容的布局尺寸，适配计算不依赖已经缩放过的 `getBoundingClientRect()`。
- 初始化、显式重置和容器尺寸变化时重新适配；节点变化只重新测量，不强制覆盖用户正在进行的视图操作。

### F-ZOOM-03 缩放、平移与适配

- 鼠标滚轮以指针位置为锚点缩放，并限制在有效比例范围内。
- 使用 Pointer Events 和 pointer capture 处理拖拽；Space 或中键平移时限定在画布范围内，并忽略输入框、文本域等可编辑元素。
- 提供放大、缩小、100% 和适配画布操作；容器尺寸变化后保持流程图可见且不裁切关键节点。

### F-ZOOM-04 静态投影与视口导航

- 小地图使用 `renderMinimap`/静态节点投影等独立入口，不渲染节点抽屉、Popover、按钮和编辑事件。
- 主画布和小地图共用同一套未变换坐标，视口框位置和比例保持一致。
- 视口框拖拽、点击导航时做边界限制；小地图作为导航辅助内容处理无障碍隐藏。

### F-ZOOM-05 缩放控制和主题统一

- 工具栏保留“查看 JSON”等已有能力，并加入缩放比例、放大、缩小、100% 和适配画布入口。
- 统一暗色/亮色主题的背景、边框、阴影、文字和悬浮层级，保证工具栏和小地图不被节点遮挡。
- 清理无法解析的 CSS 尺寸变量，避免依赖硬编码颜色和重复的内联布局规则。

### F-QA-01 编辑器交互回归

- 验证三步切换、发布校验、发布成功、取消和返回操作不会重复触发或误关闭。
- 验证初始居中、滚轮缩放、Space/中键平移、重置、适配画布和窗口缩放。
- 验证小地图不打开节点业务弹层，视口框拖拽与主画布同步，节点增删后仍能正确测量。
- 验证只读态、暗色/亮色主题、嵌套 Tab 和无流程节点等边界场景。

## 非功能要求

- 性能：小地图不重复挂载完整业务节点，缩放和平移过程中避免无意义的全量状态更新。
- 可用性：缩放范围、操作反馈、按钮禁用态和键盘行为清晰；编辑器不抢占表单输入和页面滚动。
- 可维护性：缩放状态、坐标换算和尺寸测量集中管理，组件 API 命名保持现有项目风格。
- 兼容性：不改变流程模型 JSON、节点编辑协议、发布接口和现有只读展示能力。

## Acceptance Gates

1. 编辑页由 `FaFullContentModal` 承载，步骤位于标题栏中间，发布和取消位于标题栏右侧，页面不出现重复操作按钮。
2. 初次打开、适配画布和容器尺寸变化后流程图可读、居中且不被裁切；节点结构变化不会造成缩放计算抖动。
3. 滚轮缩放以指针为锚点，平移不会粘滞或影响输入控件，缩放比例始终在边界内。
4. 小地图只提供静态导航，视口框拖拽和点击导航有边界限制，且与主画布位置一致。
5. 缩放/平移只有一个状态控制实现；TypeScript 检查和受影响页面的交互回归通过。

## 实施与验证记录

- 分支横线二次修复：人工反馈 80% 缩放时仍有外侧细线，原先“整条边框 + 背景遮罩”仍会留下缩放残边。现改为分支列分别绘制上下连接线，首列从中心开始、末列到中心结束，容器边框透明并停用旧遮罩；条件、并行、包容及嵌套分支共用此规则。`F-ZOOM-05` 保持 🔍验证中，需在亮/暗主题及 80%、100%、125% 比例下复验。
- 暗色多分支回归修复：将失效的 `.dark` 选择器改为项目实际使用的 `[data-theme='dark']`，上下分支遮罩改用画布背景变量，消除分支外侧白色横线，并恢复条件卡片和箭头的暗色样式。`F-ZOOM-05` 保持 🔍验证中，待人工确认。
- 本期已实现：单一 `useZoomPan` 控制器、独立测量层、按帧合并输入事件、Pointer Capture、局部键盘快捷键、缩放工具栏，以及静态 SVG 小地图。小地图读取主画布布局坐标，包含节点轮廓和分支连线，不挂载业务组件。
- 默认缩放范围为 10%～400%；平移限制为视口中心不超出流程图范围。节点变化保留缩放，只在位置超出边界时纠正；隐藏 Tab 保留最后有效视图。
- 标题栏使用等宽左右区域实现居中，窄容器中步骤移到标题栏第二行。只读图禁用节点编辑交互，仍可缩放、平移和查看 JSON。
- 基础/扩展表单保留挂载，保证跨步骤校验及字段保留；发布确认去重，按真实业务状态判断成功，失败保留编辑内容。
- 自动验证：8 项坐标测试通过，覆盖适配、指针锚点、缩放/平移边界、小地图导航换算和空尺寸；受影响文件 lint、样式编译和差异空白检查通过。
- 类型验证：缩放底座和弹框通过局部严格检查，流程页面接入通过定向检查。验证时临时按 Vite 配置补充源代码别名，并统一到应用的 React 18 类型；未修改依赖或项目配置。原始直接检查仍有既存 React 18/19 类型冲突，已在修改前代码复现，因此不宣称全项目类型检查通过。
- 测试复跑：在 `frontend/apps/admin` 下运行 `node --test features/fa-flow-pages/components/flow/utils/zoomPanGeometry.test.mjs`。未执行全量构建或浏览器人工验收。

## 人工验收步骤

1. 在 `/admin/flow/manage/deploy` 编辑一个测试流程：确认标题栏左侧为标题/返回，中间为三步导航，右侧为发布/取消，无重复按钮。缩窄窗口时步骤可换行且操作不重叠。
2. 修改基础信息和扩展配置，往返切换步骤，确认输入保留；清空必填项后从流程设计步骤点击发布，应回到基础信息并提示校验错误。
3. 打开流程设计，确认初次居中。围绕节点滚轮缩放，操作 `−`、`+`、比例按钮（恢复 100%）、“适应画布”，确认比例、边界及多次适配稳定。
4. 点击画布空白处，使用空格加左键、中键拖动；将鼠标移出画布后松手、切到其他窗口再返回，确认无粘滞或误开节点弹层。节点表单输入框内的空格、加减键和滚动仍正常。
5. 点击小地图空白处定位，拖动视口框到四边，确认主图同步、视口框不越界，点击小地图中的节点不会打开编辑抽屉。
6. 新增/删除节点和条件、并行、包容分支，确认小地图更新、当前缩放保留；调整窗口或侧栏宽度后确认重新适配。切换应用 Tab 后返回，确认画布仍正常。
7. 切换亮色/暗色，检查工具栏、小地图、JSON 查看和帮助；从列表“查看→流程配置”进入只读图，确认只能导航，不能增删、排序或编辑节点。
8. 在测试流程上分别验证取消、返回和重新打开；有效数据发布时只出现一个确认框，成功后关闭并刷新列表。模拟请求失败时保留内容并可重试；无节点模型不得产生无效坐标或崩溃。

以上步骤全部通过后，用户回复“验证成功”，再将本期 8 个功能标记为 ✅已完成。`F-FUTURE-01` 保持未来版本规划。

## Consequences

### Positive

- 流程编辑页面的容器、标题栏操作和步骤导航形成统一结构。
- 画布测量不再依赖变换后的 DOM 尺寸，缩放、适配和小地图更稳定。
- 小地图不再重复创建业务交互，降低渲染成本和误触风险。

### Negative

- 需要调整 `ZoomPanEditor` 的 DOM 层级、事件处理和小地图渲染入口，存在短期回归成本。
- 节点新增可视化样式时，可能需要同步维护静态小地图投影。

### Neutral

- 本次不替换流程节点组件和后端流程引擎；仍以现有 DOM 节点为主。
- 超大流程图的 Canvas/React Flow 迁移保留到后续版本，不阻塞本次底座优化。

## Alternatives Considered

- **只做 CSS 调整**：拒绝。能改善观感，但不能解决重复渲染、尺寸测量和事件边界问题。
- **立即迁移 Canvas/React Flow**：暂不采用。性能上限更高，但会同时改变节点编辑、抽屉和流程模型适配，范围过大。
- **继续复制完整节点到小地图**：拒绝。会重复挂载业务交互和状态订阅，容易产生误触和性能问题。

## Risks and Rollback

- 若尺寸观察造成适配循环，先保留显式 `fitView` 和防抖/帧合并，再回退自动重算策略。
- 若静态小地图与节点样式无法及时同步，可先使用统一的简化节点投影，不回退到完整业务节点复制。
- 若标题栏插槽在特殊 Tab 容器中无法定位挂载点，回退到当前 `.fa-main` 兼容挂载逻辑，并保留页面内容结构。
